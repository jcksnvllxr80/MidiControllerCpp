# Pi 4 → Pico 2 W Conversion

The MidiController PCB is **unchanged**. This is a **driving-board swap**: the
Raspberry Pi 4 that used to plug into the board's 40-pin header (`J35`,
`Raspberry_Pi_2_3` in `PCB/MidiControllerPCB.sch`) is replaced by a Pico 2 W
(RP2350). The old ribbon now lands on a small adapter that routes each net to the
Pico GPIO below. **All wiring, buses, protocols, and the MCP23017 expander config
stay identical to the Pi** — the firmware just speaks the same three buses.

> **This supersedes an earlier draft of this doc that described a ground-up
> redesign** (native-GPIO footswitches, UART MIDI, an I²C OLED, a 6th footswitch,
> and "tempo pulse outputs"). None of that is on the real board — see the notes at
> the bottom.

## What actually crosses the ribbon

Only 14 signal lines (plus 3V3 / 5V / GND). Everything else lives behind the two
I²C peripherals on the board.

| Group | Signal | RPi 4 (BCM GPIO) | Pico 2 W (GP) | Goes to |
|---|---|---|---|---|
| **I²C bus** (shared) | SDA | GPIO2 | **GP4** | MCP23017 `0x22` + PIC `0x04` |
| | SCL | GPIO3 | **GP5** | same bus |
| **MCP interrupts** | INT A | GPIO4 | **GP2** | MCP23017 bank-A change |
| | INT B | GPIO17 | **GP3** | MCP23017 bank-B change |
| **OLED (SPI)** | SCLK | GPIO11 | **GP18** | SSD1306 |
| | MOSI | GPIO10 | **GP19** | SSD1306 |
| | CS | GPIO8 (CE0) | **GP17** | SSD1306 |
| | DC | GPIO12 | **GP20** | SSD1306 |
| | RST | GPIO25 | **GP21** | SSD1306 |
| **Rotary encoder** | Encoder A | GPIO24 | **GP14** | quadrature |
| | Encoder B | GPIO23 | **GP15** | quadrature |
| **RGB knob LED** | Red (PWM) | GPIO16 | **GP10** | knob LED |
| | Green (PWM) | GPIO20 | **GP11** | knob LED |
| | Blue (PWM) | GPIO21 | **GP12** | knob LED |

The Pico-side assignments are the source of truth in
[`include/mc/adapters/mcu/Pins.h`](../include/mc/adapters/mcu/Pins.h); the BCM
column is what the adapter board maps each ribbon net **from**.

## What lives behind the buses (not on the ribbon)

- **5 footswitches + the rotary push button** are inputs on the **MCP23017 expander
  (`0x22`)**, read over I²C exactly as the Pi did (same IODIR/IPOL/GPINTEN/INTCON/
  GPPU/IOCON register values — see `McpExpander`). Expander bits: FSW1=A0, FSW2=A1,
  FSW3=A2, FSW4=B0, FSW5=B2, push button=B7 (the B7 selector is inverted via IPOL).
- **MIDI** is generated by writing raw bytes over I²C to the **PIC18F26K80 bridge
  (`0x04`)**, which fans every byte out to all **6 jacks: 2× DIN-5 + 4× TRS-MIDI**
  (`MIDI.py` did the same `writeRaw8`-per-byte). The Pico does **not** drive a MIDI
  UART, and the TRS jacks carry **MIDI**, not tempo.

## Key changes from the Pi

- **Form factor only.** The driver board changes (Pi 4 → Pico 2 W); the rest of the
  PCB, the expander, the PIC MIDI bridge, the OLED, the encoder, the LED, the
  footswitches, and all six MIDI jacks are untouched.
- The Pico has native USB for the editor link and on-board WiFi (CYW43); the Pi's
  network role is replaced by that.

## Corrections vs. the old "redesign" draft

For the record, so the redesign assumptions don't creep back in:

- **No 6th footswitch.** The board has 5 footswitches (plus the rotary push button).
- **No tempo/clock pulse outputs.** There is no GPIO-driven clock. The 4 TRS jacks are
  MIDI. Tempo on the Pi was set via menu/controls and is **display-only** (it was
  never even transmitted as MIDI — the only `TapTempo` reference was dead legacy code).
- **MIDI is over I²C to the PIC**, not native UART; **the OLED is SPI**, not I²C.
